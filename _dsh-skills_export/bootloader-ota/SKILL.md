# Bootloader 与固件升级

## 分区先定，代码后写

一份明确的分区表是前提，通常包含：

| 区域 | 作用 | 注意 |
|---|---|---|
| Bootloader | 只做校验、跳转、升级、自救 | 尽量小且稳定，升级中绝不重写自己 |
| 应用区 A | 运行区 | 起始地址要对齐 Flash 页 |
| 应用区 B（可选） | 新固件暂存 | 双 Bank 才有，用于并行升级与回滚 |
| 参数区 | 标志位、版本、升级状态 | 单独一页，要能原子更新 |
| 备份区（可选） | 出厂镜像 | 变砖时最后手段 |

分区要做对齐，边界写进链接脚本，别靠宏手算。

## 跳转流程

跳转前必须清理现场，顺序不要改：

1. 关全局中断（`__disable_irq()`），关掉所有用到的外设与 DMA。
2. 失能 SysTick 与所有 NVIC 中断使能位，清 pending。
3. 设 `SCB->VTOR = 应用区起始地址`。
4. 取应用区向量表前两个字：`初始 MSP` 与 `Reset_Handler`。
5. 校验 MSP 落在 RAM 范围内、Reset_Handler 落在应用区范围内且最低位为 1（Thumb）。
6. `__set_MSP(...)`，再跳转。

```c
typedef void (*pfn)(void);
uint32_t sp = *(volatile uint32_t*)APP_ADDR;
uint32_t rv = *(volatile uint32_t*)(APP_ADDR + 4);
if ((sp & 0x2FFE0000) != 0x20000000) return;   // 按实际 RAM 范围改
__set_MSP(sp);
((pfn)rv)();
```

- 应用里的链接脚本 ORIGIN 必须是分区地址，否则 VTOR 设了也没用。
- 有的芯片要求跳转前把 BOOT 引脚状态或选项字节配对，查手册。

## 镜像校验

- 至少做 CRC32 或硬件 CRC，覆盖整个镜像。
- 有条件就做签名（ECDSA 或 RSA），至少做版本号与硬件型号匹配校验，防止刷错机型。
- 校验放在**跳转前**，而不是应用启动后自检——应用起不来就没机会自检。
- 镜像头里放：魔数、版本、长度、CRC、硬件版本、构建时间。魔数和长度先校验，防止读到未写入的 Flash（全 0xFF）。

## 升级流程与掉电安全

状态机放在参数区，每一步都落盘：

```
IDLE → 收到升级请求 → 擦除暂存区 → 写入新镜像 → 校验 → 置"待切换" → 复位 → Bootloader 切换 → 运行新固件 → 置"成功"
```

- **任何一步掉电都必须能恢复**。关键点是：擦除和写入期间不能动当前运行区。
- 用"双标志 + 版本号"而不是单标志位，避免写一半的判断歧义。
- 新固件第一次启动要"喂狗确认"：跑通了才清"待切换"标志，否则下次复位自动回滚。
- 看门狗在 Bootloader 里也要喂，否则升级时间长了被复位。

## 回滚

- 双 Bank：切换 Bank 或改 VTOR 指向，失败就切回。
- 单 Bank + 备份区：失败时从备份区恢复，恢复流程本身要极简、可重复执行。
- 至少保证"Bootloader 永远可进"：留一个升级请求引脚、串口命令或按键长按。

## 常见坑

1. 应用里没改链接脚本起始地址，编译出来还是从 0x08000000 开始。
2. 跳转前没关中断，应用里第一个中断进了旧向量表。
3. VTOR 设了但向量表没按 512 字节对齐（ARMv7-M 要求）。
4. 擦除时按字节擦而不是按页擦，或者擦多了把参数区干掉。
5. 升级中途断电，参数区状态位半写，重启后进入未知状态。
6. 校验和算错（大小端、是否含头部），导致好镜像被判坏。
