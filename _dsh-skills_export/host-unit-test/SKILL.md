# 固件主机端单元测试

## 先做分层，测试才有落点

不可测的根因通常不是缺框架，是逻辑和寄存器写死在一起。按三层拆：

| 层 | 内容 | 可测性 |
|---|---|---|
| 纯逻辑层 | 协议解析、状态机、算法、校验 | 完全可测，重点覆盖 |
| HAL 接口层 | 读写寄存器、延时、收发 | 只留接口，测试时替换 |
| 驱动实现层 | 具体芯片寄存器序列 | 不强求单测，靠硬件在环 |

原则：纯逻辑层不允许 `#include` 任何芯片头文件。

## 两套方案

| 方案 | 适合 | 特点 |
|---|---|---|
| Unity + CMock + Ceedling | 纯 C 项目，团队小 | 约定强，自动生成 mock，上手快 |
| GoogleTest + CMake | 已有 CMake、混 C/C++ | 生态好，断言强，需要自己做打桩 |

最小 CMake 结构：

```
firmware/
  src/logic/          # 被测代码
  src/hal/hal.h       # 只声明接口
  test/
    hal_mock.c        # 测试用实现
    test_parser.cpp
  CMakeLists.txt
```

## HAL 打桩三种手法

1. **链接期替换**：把 `hal_mock.c` 和被测代码一起编译，不链真实实现。最简单，适合一开始就分层的项目。
2. **`--wrap`**：`-Wl,--wrap=HAL_Read` 把调用重定向到 `__wrap_HAL_Read`，真实实现仍可调 `__real_HAL_Read`。适合不想改源码的老项目。
3. **函数指针表**：HAL 用结构体函数指针注入，测试时换表。最灵活，但要改架构。

## 必须模拟的东西

- **时间**：不要真 `delay`。把 `now_ms()` 抽成接口，测试里手动推进虚拟时钟。
- **中断**：不要真中断。把 ISR 里的处理逻辑抽成 `xxx_on_event()` 普通函数，测试直接调。
- **并发**：单线程测试跑不了竞态，只能测状态机分支；竞态靠代码审查和硬件在环。
- **随机与未初始化内存**：测试里把缓冲区填成 0xAA 再跑，能暴露"忘了初始化"。

## 覆盖率

```
gcc --coverage -O0
gcovr -r . --html-details coverage.html
```

- 先追分支覆盖率，不追行覆盖率。状态机的每个跳转都要有用例。
- 覆盖率是下限不是目标。80% 分支覆盖对协议解析够了，对安全相关逻辑要更高。
- 排除启动文件、厂商库、纯寄存器胶水代码，否则数字没意义。

## CI 接入

- 每次提交跑：编译（`-Werror`）+ 单测 + 覆盖率报告。
- 用主机编译器交叉验证一遍 32/64 位差异，`size_t` 宽度问题会在这里暴露。
- 保留一份 `-fsanitize=address,undefined` 的构建，能抓出越界和 UB。
