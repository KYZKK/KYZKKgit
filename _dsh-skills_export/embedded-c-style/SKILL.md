# 嵌入式 C 写法与陷阱

## volatile

`volatile` 只保证"每次都从内存读/写"，**不保证原子性，也不保证顺序**。

该用的地方：

- 中断与主循环共享的标志变量。
- 硬件寄存器（通常已由厂商头文件定义为 volatile）。
- 在中断里修改、在主循环里轮询的计数器。

不该指望它的地方：

- 多字节变量的原子性 —— 需要关中断或用原子操作。
- 内存屏障 —— 需要 `__DMB()` / `__DSB()` 或 C11 `atomic_thread_fence`。
- 防止编译器重排 —— volatile 对编译器重排的约束有限，跨外设的顺序要显式屏障。

## 位操作

- 置位用 `|=`，清位用 `&= ~`，不要用 `=` 覆盖整寄存器（会踩到别的位）。
- 读-改-写不是原子的。中断里也操作同一寄存器时，要么关中断，要么用芯片提供的 BSRR / set-clear 寄存器。
- 移位常量注意类型：`1 << 31` 是有符号溢出（UB），写 `1u << 31`。
- 掩码宽度与实际位宽对齐，别把 8 位字段当 16 位处理。

## 位域

- 位域的内存布局由编译器决定（位序、是否跨字节），**不要用它映射硬件寄存器或通信协议**。
- 需要精确布局时用显式掩码和移位，或 `static_assert(sizeof(struct) == N)` 兜底。
- 对位域成员不能取地址，也不能保证原子访问。

## 中断与主循环

- 中断服务程序要短：只做搬运和置标志，复杂逻辑丢回主循环。
- 共享变量：单字节标志可以直接读写；多字节要临界区保护，或者用无锁的单生产者单消费者环形队列。
- 不要在中断里调用 `printf`、`malloc`、浮点库（除非确认可重入且栈够）。
- 中断优先级与临界区要一起设计：`__disable_irq()` 会连高优先级中断一起挡，必要时用 BASEPRI 只挡低优先级。

## 整数与未定义行为

- 整数提升：`uint8_t a, b; a + b` 会提升成 `int`，比较和溢出行为随之改变。
- 有符号溢出是 UB，优化器会据此做出反直觉的推断。涉及溢出的运算一律用无符号。
- 右移负数、越界访问、未初始化读，都是 UB。开发期把 `-Wundef -Wconversion -Wshadow` 打开。
- 指针强转要过对齐检查，尤其是从通信缓冲区里取结构体。

## 内存

- 嵌入式默认不用堆。需要动态生命周期时优先用静态池或固定大小块分配器。
- 栈大小要算：最深调用链 + 最大局部变量 + 中断嵌套开销，再乘 1.3 留余量。
- 大数组一律放静态区，不要在栈上开几 KB 的临时缓冲。

## 优化相关的坑

- `-O2` 下 `while(!flag);` 若 flag 不是 volatile，会被优化成死循环。
- `-flto` 会跨文件内联，`__attribute__((weak))` 和中断向量表的可见性要重新确认。
- 空循环延时会被优化掉，用 `__NOP()` 或 DWT 计时。
- 调试时用 `-Og` 或 `-O0`，量测性能时回到发布配置，别用调试构建下结论。
