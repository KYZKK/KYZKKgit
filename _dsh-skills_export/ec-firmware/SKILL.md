# EC 固件开发

## EC 是什么

主板上独立的一颗 MCU，负责主机"睡觉时也得干活"的那些事：键盘、电池、温度、风扇、电源时序、开关机。通过 eSPI（新平台）或 LPC（老平台）与 PCH 通信，对外表现为 ACPI 里的 EC 设备。

> 芯片型号、寄存器、eSPI 通道映射、GPIO 用途全部以具体平台的设计文档与芯片 datasheet 为准。下面只给通用结构，不代替手册。

## 常见芯片与工具链

- ITE（IT8xxx 系列）、ENE（KB90xx 系列）、Nuvoton（NPCE 系列）是三个主要来源。
- 各家都有专用 IDE 或 GCC 工具链，烧录多用 eSPI/I2C 或专用调试口。
- 平台侧通常还有一份 EC 配置表（引脚用途、传感器映射、电池参数），改硬件时要同步改。

## 主机通信

- eSPI 通道一般分：Peripheral（带外设访问）、Virtual Wire（虚拟线，传 SLP_S3/S4/S5、SUS_WARN 等）、OOB、Flash。
- LPC 时代用 I/O 端口：`0x60/0x64` 给键盘控制器，`0x62/0x66` 给 ACPI EC（命令/数据）。
- 通信协议是"命令 + 数据"的握手：主机写命令到 0x66，EC 置 IBF/OBF 标志，主机轮询状态位后读写数据。
- **握手时序错一步就表现为"主机读不到电池信息"或"EC 超时"**，抓 eSPI 分析仪比看代码快。

## ACPI 接口

- EC 在 ACPI 命名空间里是一个 `PNP0C09` 设备，DSDT 里通过 `EC0`/`H_EC` 之类的名字暴露方法。
- 常用方法：`_REG`（声明 EC 就绪）、`_Qxx`（查询事件，EC 置位后由 ACPI 调用分发）、`_CRS`（资源）。
- 电池通常在 `_BIF`/`_BIX`/`_BST` 里读，数据来自 EC 的 SMBus 转手。
- 改 EC 事件编号要同时改 DSDT 里的 `_Qxx`，两边对不上就是"事件丢了"。

## 键盘

- 矩阵扫描：逐行拉低、读列，加去抖（通常 5～20ms 窗口）。
- 多键同时按下要处理 ghosting，必要时用二极管或分区扫描。
- 扫描周期影响手感，太慢会丢快速连击，太快会增加功耗与 EMI。
- 快捷键（Fn 组合）通常走 EC 直接发扫描码或走 ACPI 事件，两条路不要混。

## 电池与充电

- 智能电池走 SMBus（常见地址 0x0B），读 `BatteryStatus`、`BatteryMode`、`Voltage`、`Current`、`Temperature`、`CycleCount`。
- 充电流程通常是状态机：预充 → 恒流 → 恒压 → 截止，加上温度保护与超时保护。
- 常见故障：不充电（先查适配器识别与 ID 脚）、充电电流跳变（查采样与环路）、电量跳变（查库仑计校准）。
- 保护参数（过压、过流、过温）改动前先确认电芯规格书。

## 温度与风扇

- 温度来源：EC 内部传感器、SMBus 温度芯片、CPU/GPU 通过 PECI 或 eSPI 上报。
- 风扇曲线通常分段线性，注意滞回（hysteresis），否则会在阈值附近反复启停。
- 风扇转速用 PWM 加测速反馈，堵转要能检测并上报。
- 热保护要有分级：降频请求 → 强制风扇 → 关机。

## 电源时序

- 关键信号：`PWRBTN#`、`RSMRST#`、`SLP_S3#/S4#/S5#`、各路电源的 `PG`。
- 上电顺序必须按平台要求，任何一路提前或滞后都可能起不来或损伤器件。
- 关机要做"优雅下电"：先通知主机，等 SLP 信号，再切电源，最后断电。
- 长按电源键强制关机要有计时（通常 4 秒）与防抖。

## 固件更新与恢复

- 多数平台支持 EC 通过 eSPI 由主机侧工具更新，也有独立烧录口。
- 一定要有双区或备份，EC 变砖往往整机不亮且不好救。
- 更新前确认电池电量或适配器在位，中途掉电要有恢复路径。

## 排查顺序

1. 整机不亮：先量待机电压、RSMRST、EC 复位、EC 时钟。
2. 键盘无反应：先看矩阵扫描波形，再看 eSPI/LPC 的 0x60 端口有没有数据。
3. 电池不识别：先抓 SMBus 波形，确认地址与 ACK。
4. 睡眠唤醒失败：查 SLP 信号时序与 `_Qxx` 事件是否发出。
5. 风扇狂转：查温度读数是否为默认值（传感器没读到时常退化成满转）。
